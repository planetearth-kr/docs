# PlanetEarth 가이드 문체 가이드

docs 문서를 쓰거나 노션 변경을 반영할 때 따르는 규칙이다. 목표는 **사람이 쓴 것처럼 자연스럽고, 문서 전체가 같은 목소리로 읽히는 것**이다.

## 절대 바꾸지 않는 것

다듬는 것은 문장과 형식뿐이다. 아래 정보는 글자 그대로 유지한다. 없는 정보를 추측해서 더하지도 않는다.

- 숫자, 확률, 가격, 시간, 수량, 좌표, 레벨
- 명령어와 그 인자, 아이템·NPC·지역·랭크 이름
- 링크 주소, 이미지 경로, frontmatter의 `slug`
- 규칙의 조건과 예외, 처벌 수위, 조항 번호
- `policy/` 문서(규정, 약관, 티켓, 환불, 제약사항)는 법적 효력이 있는 글이다. 맞춤법과 띄어쓰기만 고치고 문장 구조와 의미는 그대로 둔다.
- `events/` 문서는 지난 행사 기록이다. 맞춤법과 띄어쓰기만 고친다. 단, 머리 정보는 `진행기간: 2023년 1월 12일 ~ 2023년 1월 24일`, `주제: ...`, `수상부문: ...` 형식으로 맞춘다(노션의 `[진행기간]`, `2023/01/12`, `→` 표기, DB 속성 `- 진행기간: 2023-01-12 → ...`도 이 형식으로 옮긴다).

## 문체

- 설명은 합니다체로 쓴다. 독자에게 무언가를 하라고 안내할 때는 "~하세요"를 쓴다. 반말과 "~해요"는 쓰지 않는다.
- 한 문장에는 한 가지 내용만 담는다. 쉼표로 길게 이어진 문장은 나눈다.
- 같은 대상은 문서 전체에서 같은 이름으로 부른다. 아래 용어집을 따른다.

## AI처럼 읽히는 표현 빼기

다음 표현은 정보가 없으니 지우거나 구체적인 문장으로 바꾼다.

- 군더더기 도입과 마무리: "~에 대해 알아봅시다", "이번 문서에서는 ~를 소개합니다", "지금까지 ~를 살펴보았습니다", "즐거운 플레이 되세요!"
- 빈말: "다양한", "효과적으로", "중요한 역할을 합니다", "~하는 것이 중요합니다", "매우", "꼭" (꼭 해야 하는 일이 아닌데 쓴 경우)
- 문장 사이에 끼어든 감탄문, 과한 느낌표, 꾸밈용 이모지. 노션 callout 앞에 붙은 이모지도 지운다(admonition이 이미 아이콘을 보여준다).

## 형식

- **제목**: 본문에 `#` 제목을 쓰지 않는다. 페이지 제목은 frontmatter `title`이 표시한다. 본문은 `##`부터 시작하고, 레벨을 건너뛰지 않는다(`##` 다음에 바로 `####`를 쓰지 않는다).
- **명령어**: 인라인 코드로 쓰고, 따옴표나 굵게로 감싸지 않는다. 인자는 원문 표기(`[인자]`)를 그대로 쓴다. 예: `/t claim`, `/낚시도감`, `/n add [마을]`
- **메뉴 경로**: 화살표로 쓴다. 예: 메인 메뉴 → 포인트 상점
- **굵게**: 꼭 기억해야 하는 조건이나 숫자에만 쓴다. 한 문단에 한두 군데를 넘기지 않는다.
- **admonition**: 종류별 용도를 지킨다.
  - `:::caution`: 금지, 처벌, 손해를 볼 수 있는 일
  - `:::tip`: 알면 편한 요령
  - `:::info`: 참고 정보
  - `:::note`: 본문에 대한 보충 설명
- **목록**: 순서가 있으면 번호 목록, 없으면 `-` 목록을 쓴다. 목록 항목 끝에는 마침표를 찍지 않는다. 단, 항목이 완전한 문장이면 마침표를 찍는다.
- **표**: 표 머리글을 둔다.
- **줄바꿈**: 마크다운은 그냥 줄을 바꾸면 한 문단으로 붙는다. 노션의 `<br />` 중 의미 있는 줄바꿈(Q&A, 명령어와 설명, 서명, events 기록)은 줄 끝에 `<br />`를 남긴다. 설명 문장끼리는 한 문단으로 붙여도 된다.
- **숫자와 단위**: 붙여 쓴다(3칸, 24시간). 숫자 표기(쉼표 유무 포함)는 원문 그대로 둔다.
- **이미지**: alt는 영문 kebab-case로 내용을 설명한다(`overview`, `section`처럼 내용이 없는 alt는 쓰지 않는다). 파일은 `static/img/docs/<문서 경로>/<alt>-NN.<확장자>`에 둔다.
- **링크**: 내부 링크는 slug 절대경로로 쓴다(`/towny/basics`). 링크 문구는 "여기"가 아니라 대상 문서의 이름으로 쓴다.
- **frontmatter `description`**: "<주제>를 설명합니다." 형태의 한 문장으로 쓴다. `events/` 기록 문서는 "<행사>를 소개합니다."로 쓴다.
- **파일 이름**: slug의 마지막 부분과 같게 짓는다(`/towny/basics` → `towny/basics.mdx`). 키 순서는 `slug`, `sidebar_position`, `sidebar_label`, `title`, `description`이다.
